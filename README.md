# kubewing 🪽

Keyboard-driven native desktop UI for Kubernetes: `kubectl` + grep/watch/diff + tabs/splits. See [Plan.md](Plan.md).

## What works today

- Live table for any resource (`po`, `deploy.apps`, CRDs …) of any kubeconfig context; columns from server-side Table output.
- A kubeconfig context that sets a namespace starts in it: the first pane at launch (current context) and new tabs/splits, and `⌘O` prefills it when you pick that context. Contexts without one start in all namespaces.
- One watch stream per source (`as=Table;includeObject=Object`): cells and objects come from the same resourceVersion.
- Keyed diff by UID: changed cells, "changed, not visible" marker, added/deleted rows (delete + recreate = remove + add), AGE never counts as a change, noise (resourceVersion, managedFields, heartbeats) ignored.
- Splits/tabs (dockview): drag a divider to resize, drag a pane to rearrange; `⌘D` split stacked, `⌘⇧D` split side by side (deliberately swapped vs. iTerm), `⌃D` or `⌃⇧D` close the pane, `⌘T` new tab, `⌘W` close the tab (it asks first if the tab holds more than one pane), `⌘1`–`⌘8` go to that tab and `⌘9` to the last (shown in the tab header), `⌘⇧[ ]` cycle tabs (from anywhere, also a shell), `⌘[ ]` cycle panes, `⌘⌥←→↑↓` move to the tile in that direction. `⌘⇧⏎` maximizes the focused pane to the whole tab (as iTerm does) and back; the other panes stay open behind it (their watches and shells keep running), and a small `⤡N` badge at its top right says so (N = panes hidden; its tooltip says more) — a click on it, `⌘⇧⏎` again, moving focus to another pane, a split or closing a pane shows them all again. Per tab; a tab with a single pane has nothing to maximize. `⌃⇥` / `⌃⇧⇥` switch tabs in MRU order: a quick tap flips to the previous tab, and holding `⌃` shows a switcher (`⇥` steps, release commits, `Esc` cancels). `⌃D` stays out of text fields, where it is forward-delete; in a terminal `⌃D` belongs to the shell (ending it closes the pane), and `⌃⇧D` closes the pane of a shell that won't end. Splits on the same source share one watch.
- Filter bar: `/` grep (applies as you type; space-separated terms must all match, `!x` excludes rows containing x, `"a b"` is one term, `\!` a literal `!`; a negated term applies once finished — a space after it, `⏎` or leaving the field — since `!c`, `!co` … would otherwise blank the table and bring rows back as you type), `l` label selector, `c` CEL filter over the object `o` (`o.status.containerStatuses.exists(c, c.restartCount > 3)`). Labels and CEL are drafts until `⏎`: a half-typed value would match nothing, so while typing the table stays as it is and the field shows what the draft would show (`→ 2 / 3`; `≥` when a wider label selector may match objects not loaded yet), or why it can't apply (parse error with a caret, not a bool). `⏎` or leaving the field applies (an invalid draft stays in the field, red, with the reason as tooltip), empty + `⏎` clears. CEL completes field paths from the pane's live objects (`o.status.` → the keys found there, with type and how many objects have them; also inside `exists(c, c.…)`; a key that isn't an identifier goes in as `["app.kubernetes.io/name"]`, `.?`/`[?` stay optional, and typing `["` completes keys too — Kubernetes' `__dot__` escaping is for typed schemas on the apiserver and doesn't apply to kubewing's schemaless objects), the common functions, and after a field and a space (or on `=`, `!`, `<` …) the operators that fit its type (a string gets `==`, `!=`, `in […]` and the ordering ones, which also order RFC 3339 timestamps; a bool `&&`/`||` first; a map or list only `==`/`!=`); `⇥` completes, `↑` in an empty field recalls recent filters. Filter changes keep the watch and the diff state. Errors other than a missing field (which just doesn't match) show in the status line.
- Hide healthy: `h` (or the `hide healthy` checkbox in the pane header) hides what needs no look. Pods: Running with every container ready (sidecars included, completed init containers ignored). Deployments and StatefulSets: the controller has seen the latest spec (`observedGeneration`), and current, updated, ready and available replicas all equal `spec.replicas`. ReplicaSets: the same without updated. DaemonSets: scheduled, updated, ready and available all equal desired, none misscheduled. Anything terminating stays visible, other kinds aren't affected (no checkbox). It is a pipeline stage (`hideHealthy: true`), evaluated live: an object that becomes healthy drops out, one that stops being healthy comes back.
- `j/k`, `g/G` or `⌥↑/⌥↓` first/last row, `⌘O` open context/resource/namespace.
- Detail view in a read-only Monaco editor: `⏎`/`y` YAML, `d` side-by-side diff of the previous vs. current normalized object, `⇧D` `kubectl describe` (with events — `d` is the diff toggle here, so describe keeps `⇧D` in this view), `⌘F` find, `w` wraps long lines on/off (on by default; holds for the session, in YAML, diff and describe), `Esc` closes. In a diff (object or describe) `j`/`k` or the `↓`/`↑` buttons in the header jump to the next/previous change, wrapping around; the header shows which one (`2 / 5`), and the view opens on the first. In the YAML, `=` on a line filters the pane by that field's value and `!` by "not this value" (objects without the field included); fields inside lists become `exists()`.
- Describe diff: in the describe view `d` diffs against the previous look at the same object (by UID, this session), `r` re-runs describe. Unlike the object diff it shows what describe adds (events, counts); relative times (event ages, heartbeats, lease renewals) are blanked and tables re-aligned, so only real changes show. It compares looks, not watch history: changes between two looks are summed up.
- Object actions: `⌘C` copies the selected row's name (in text fields, the YAML view and terminals `⌘C` is the normal copy), `d` describe, `⌘⌫` or `Del` delete (UID precondition, so a recreated object of the same name is never hit), `x` exec into a pod (bash, else sh) in a terminal pane below (xterm.js; every key goes to the shell except `⌘` chords, `⌃⇥` and `⌃⇧D`; `⌃D` or `exit` ends the shell and the pane goes with it, `⌘W` closes the tab as anywhere else; `⌘F` finds in the output and scrollback as Monaco's find does: matches highlight as you type, `⏎`/`⇧⏎` or `⌘G`/`⌘⇧G` step (also from the shell), `Aa`/`ab`/`.*` (`⌥⌘C`/`⌥⌘W`/`⌥⌘R`) toggle case, whole word and regex, `Esc` closes back to the prompt and `⌘F` reopens with the last query; a session that never started, or a shell that exits non-zero before the first keystroke, keeps its pane so the reason stays readable, and `⌃D` closes it once read), `f` port-forward on 127.0.0.1: the dialog lists the pod's running forwards (✕ stops one; from the keyboard `⇧⇥` goes up into them, `↑`/`↓` pick, `x` or `⌫` stops, `⇥`/`Esc` back) and offers the declared ports not forwarded yet, each locally on the same port, except below 1000 (binding needs root), which gets 8000 added (`8053:53`, `8443:443`) — one is pre-filled; with several, a list shows each with its name, protocol and container (type a number or name to narrow it; `⏎` adds the highlighted one and then nothing is highlighted, so the next `⏎` forwards: one port is `⏎ ⏎`, another one `↓ ⏎` in between; `⇥` completes to the best match). UDP-only ports are listed but can't be picked: port-forward carries TCP only, as with kubectl. Each port is its own forward, listed and stopped on its own. If one fails (a typed local port below 1024, a port in use), the others still start; the failed ones stay in the field with their error, and the port list closes so the error stays readable (typing opens it again). The `⇄ N` badge in the tab bar (or `⌥⌘P`) lists all forwards, also those whose pod is no longer shown; `↑`/`↓` pick, `x`, `⌫` or ✕ stops one. With more than one container to enter, `x` asks which one: the pod's containers, then init, sidecar and ephemeral ones, each with its state; ones that aren't running are listed but skipped. The default (`kubectl.kubernetes.io/default-container`, else the first container) is highlighted, so `x ⏎` enters it; `j/k` move, `Esc` cancels. A pod with a single one goes straight to its shell. A confirmation, if the rule asks for one, names the container. `b` starts a debug container in the pod (`kubectl debug -it`): a dialog asks for the image (prefilled from `debug.image` in `config.yaml`, else the last one that started; `↓` lists the configured one and the last 10 that started, typing narrows them; ✕ on a history entry forgets it), the container whose processes it shares (the pod's default; empty = none) and the profile (`general`, `baseline`, `restricted`, `netadmin` for tcpdump, `sysadmin` for privileged; default from `debug.profile`). All three are completion fields as in `⌘O` (`↓` lists the choices, `⇥` completes); a target or profile that isn't one of them is refused in the dialog. `⏎` on a highlighted suggestion only takes it into the field; the next `⏎` starts, from any field. The shell opens in a pane below, with the image and target in its header; until the container runs, the pane shows its waiting state and the kubelet's events for it (`Pulling image …`, `Pulled …`), and a container that can't start (bad image) keeps its pane with the reason. Like `kubectl debug`, the ephemeral container stays in the pod (terminated) until the pod is gone.
- Node shell (a privileged pod on a node, like ops-toolbelt's `hacks/ops-pod`): `⌥⌘O` from anywhere, or "node shell…" in the context menu of a node or pod row. The dialog's node is prefilled from the selected row (the node itself, or the node a pod runs on); the context's nodes are listed right away with pool, zone and state (not ready, cordoned), and `⏎` takes the prefilled one. The nodes come from the shared nodes watch: with a nodes pane open it's that pane's data, no extra list call; otherwise the dialog starts the watch, which stops 30 s after the dialog closed. Shared watches are keyed by the resolved resource, so `no`, `node` and `nodes` panes share one too. The image field shares its history with debug containers (default `opsPod.image`); the namespace completes from the context's namespaces (empty = `default`). Checkboxes: chroot into `/host` (the shell runs on the node; implies host root), host root (the node's `/` at `/host`) and host network; host root and host network are on by default. Optionally a persistent volume is mounted at a path (default `/pv`, not `/` or under `/host`): the field completes the context's PVs (from the shared `persistentvolumes` watch) and only bound ones can be picked, since a pod mounts a PV through its claim — so the pod then runs in the claim's namespace. The namespace and checkboxes of the last pod that started are remembered in `history.yaml` (across restarts) and win over `config.yaml`. The pod is named `ops-pod-kubewing-<user>-<hex>` (the OS login, as the script's `whoami`), privileged with host PID, bound to the node via `nodeName` (so cordoned and tainted nodes work; every taint is tolerated), and labelled `app=opspod`. "show YAML…" renders the pod kubewing would create as editable YAML; edited, that YAML is what starts (kubewing checks it stays a `v1` Pod on the prepared node with the `ops-pod` container, name and namespace — everything else, e.g. `priorityClassName` or extra volumes, is yours), `⌘⏎` starts it, `esc` goes back to the form. The shell opens in a pane below with node, pod, image and settings in its header; the pod is deleted when the shell ends, the pane is closed or the app quits (quitting waits up to 10 s for the deletes). See [Why a dedicated node-shell pod](#why-a-dedicated-node-shell-pod-vs-kubectl-debug-node) for how this differs from `kubectl debug node/…`.
- Edit (as `kubectl edit`): `e` on a row, or in its YAML view, reads the object fresh from the API server (not the watch) into an editable Monaco editor; keys there are text, only `⌘` chords and `⌃⇥` reach the app. `⌘S` (or `⌘⏎`) checks the edit and has the server dry-run it, then shows a side-by-side diff of the object now vs. as the server would store it (defaults and admission webhooks applied; both normalized as in the detail diff); `j`/`k` step through the changes, `⏎` writes it, `Esc` goes back to editing. Only what changed is sent (a JSON merge patch, field manager `kubewing`), with the opened `resourceVersion` as a precondition: if anyone changed the object since it was opened, the write is refused as a conflict instead of overwriting them. apiVersion, kind, name, namespace and uid can't change (that would be another object). Anything refused (invalid YAML, a webhook, a conflict, "no changes") shows below the editor with the text kept, also when the write itself fails after a confirmation. `Esc` with changes asks once; the second `Esc` discards them. Read-only contexts refuse `e` before the editor opens; `confirm: [edit]` in a context rule confirms after the preview (`Esc` there goes back to it). Server-side apply and recreate are still open (see [Plan.md](Plan.md)).
- Context menu: `⌘⏎` or right-click on a row lists every operation on it (view YAML, edit YAML, describe, diff, copy name, jump to, exec, port-forward, delete) with its shortcut from the live keymap; unavailable entries say why ("needs a pod", "read-only context", "no change seen yet"). `j/k` move, `⏎` runs, `Esc` closes. It's generated from [actions/registry.ts](frontend/src/actions/registry.ts): a new row action is one entry there, and a unit test fails for any `object.*` command that has none.
- Jump to related resources: `⌘J` on a row (also in its YAML view, or "jump to…" in the `⌘⏎` menu) lists where it leads (its **events** too, see above). **namespace**: "pods in shop" (the same resource narrowed to the row's namespace, filters kept; from an all-namespaces pane) and "namespace object shop" (the Namespace itself). **owners**: the `ownerReferences` chain up (pod → replica set → deployment, and on through Gardener and other CRD owners; the controller first, `↑` for each level), each looked up by metadata only and checked by UID, so a deleted or recreated owner is listed disabled with why. **owned**: what the row is known to run, counted: deployments → their replica sets and pods, replica sets, statefulsets, daemonsets and jobs → pods, cron jobs → jobs, nodes → their pods (all namespaces), a custom resource with a scale subresource → the pods its `labelSelectorPath` selects. Direct children must also name the row in their `ownerReferences` (selectors can overlap); a deployment's pods go by its selector. Anything else (a CRD owning config maps) is found by "scan for owned…", which lists every resource type's metadata in the row's namespace and matches the owner's UID; it runs only on request, skips types it can't list (and says how many), and for a cluster-scoped owner (all namespaces) asks with a second `⏎` first. `j/k` move, `⏎` jumps in place, `⇧⏎` opens the target in a split below, `Esc` closes. A jump is an ordinary pane: the target is a source plus filters (`o.metadata.name == "web"`, `o.metadata.ownerReferences.exists(r, r.uid == "…")`, a label or field selector; a field selector shows as a chip in the header), so the filter bar shows why it holds what it holds, and clearing the filter shows the siblings. In place, the pane keeps a history as a browser does: jumps and `⌘O` to a new source (context, resource, namespace or selectors; the same source again is no step) are its steps, while filter edits are part of the view they're on and come back with it. `⌘←` goes back, `⌘→` forward again to the view just left (in the table; in text fields they stay start/end of line), each time with the row that view had selected again; a new jump or `⌘O` after going back drops the forward history. The header shows where each leads (`⌘← pods · ⌘→ deployments.apps`). Splits and new tabs start without history. Read-only (metadata only, no tokens): works on read-only contexts and on deleted rows (their last state).
- Events of a row: `v` (also in its YAML view), or the **events** entry at the end of the `⌘J` jump menu (counted; `⇧⏎` opens them in a split below, next to the row), turns the pane into the events about that object, as a jump does: `events` with the field selector `involvedObject.kind=Pod,involvedObject.name=web-0` (the chip in the header) in the object's namespace, all namespaces for a cluster-scoped one (a node's events are in `default`). By kind and name, not UID, as `kubectl describe` does: the kubelet records a node's events with the node's name as its UID. It's a live watch like any pane, so new events show up as they happen; `⌘←` goes back to the row. Works on deleted rows too (events outlive their object for a while), not on an event row. No events yet can still be jumped to (to watch for them).
- Cheat sheet: `?` (again or `Esc` closes) lists every shortcut by section, with the context a key is scoped to, read from the live keymap — so `keybindings.yaml` overrides show up as they are. It's built from [keys/cheatsheet.ts](frontend/src/keys/cheatsheet.ts), and a unit test fails for any command that no section mentions.
- Native menu bar (macOS app): File / Object / View / Pane / Tab / Help list the app's commands, built from the live keymap in [keys/appMenu.ts](frontend/src/keys/appMenu.ts); a click goes to the same dispatcher as a key. Global ⌘ chords are the items' native key equivalents (so `keybindings.yaml` changes show there too); scoped and plain keys appear in the label instead, so a menu shortcut never fires inside a text field. Wails' default menu is replaced: no ⌘W "Close Window" (⌘W closes a tab) and no ⌘R "Reload". Edit keeps ⌘C/⌘V/⌘A/⌘Z for text fields.
- Safety model, decided in Go: per-context label and color on pane frame, header and tab; read-only contexts refuse delete, exec, debug and node shells (describe and port-forward still work); delete always asks, other actions per rule; strict rules require typing the object name. Every mutation goes through a single-use, 60 s token bound to the exact object.
- Config in `~/.kubewing/` (or `$KUBEWING_HOME`), read-only and optional (the one file kubewing writes there is its own `history.yaml`: recent debug container and node-shell images, the last node shell's namespace and checkboxes, and the window's size: it reopens in it, centred, maximised or fullscreen again); `⌘⇧,` reloads. Problems show in a banner and fall back to defaults. See [testdata/config/](testdata/config/) for a commented example:
  - `config.yaml`: theme, extra diff ignore rules, per-context safety rules (`match` glob, `label`, `color`, `readOnly`, `confirm` (`delete`, `exec`, `debug`, `opspod`), `strict`), debug container defaults (`debug.image`, `debug.profile`), node-shell defaults (`opsPod.image`, `opsPod.namespace`, `opsPod.chroot`, `opsPod.hostRoot`, `opsPod.hostNetwork`; until a pod ran), terminal scrollback (`terminal.scrollback`, lines, default 10000).
  - `keybindings.yaml`: `{key: cmd+k, command: row.down, when: [table]}`; `command: none` unbinds.
  - `themes/<name>.yaml`: overrides for the tokens in [theme.css](frontend/src/theme.css).
- `⌘O` completion for resource and namespace: ranked by exact > prefix > substring > fuzzy over names, short names, singular and kind (`po`, `pdb`, `Deployment`). Suggestions show group, scope and short names, with the typed letters highlighted. A plural served by two groups (`machines`) completes to its qualified name. Fields open with their value selected; the list opens on typing (or `↓`). `⇥` completes, `⏎` completes and opens, `⌥↑/⌥↓` first/last suggestion, `Esc` closes the list, then the dialog. Unknown text still opens as typed.
- Cluster catalog (resource types + namespaces per context), fetched in the background once a pane is open on that context. It never connects on its own, so it never triggers exec-plugin logins. Refreshed by metadata-only CRD/namespace watches, on resolve misses and every 5 min. Partial discovery (an aggregated API down) and forbidden namespace lists degrade to a hint.

## Why a dedicated node-shell pod (vs `kubectl debug node`)

`kubectl debug node/<n> -it --image=…` does almost the same thing — it also creates a real pod bound to the node with host PID and the node's `/` at `/host`. For a generic cluster the two are interchangeable, and the node shell deliberately reuses that shape. The differences are Gardener-specific and are the reason ops-toolbelt's `hacks/ops-pod` exists:

- **Tolerates every taint.** The node shell sets `tolerations: [{operator: Exists}]`; `kubectl debug node` sets none. Binding via `.spec.nodeName` bypasses *scheduling* (so `NoSchedule` is moot either way), but `NoExecute` taints are still enforced by the eviction controller — so on a Gardener etcd pool (tainted `pool.worker.gardener.cloud/dedicated-for=etcd:NoExecute`) `kubectl debug node` gets **evicted**, the node shell stays.
- **Reaches the seed API server.** The pod carries `networking.gardener.cloud/to-seed-apiserver: allowed`; on a seed with network policies a plain debug pod can't.
- **No istio sidecar** (`sidecar.istio.io/inject: "false"`), so a mesh-enabled namespace doesn't inject one into the shell pod.
- **Auto-cleanup.** The pod is deleted when the shell ends, the pane closes or the app quits; `kubectl debug node` leaves it behind.
- **`priorityClassName`** (e.g. `system-cluster-critical`, to land on a full node) is offered as a commented line in "show YAML…" — uncomment it, or add anything else, before starting.

Everything the two share is unchanged: both need a privileged namespace (PodSecurity applies equally — the `default` namespace's `baseline` standard rejects host namespaces, hostPath and privileged, so use e.g. `kube-system`), and both can only mount a PV through a PVC in the pod's own namespace. kubewing's value is the UI around it (node/PV completion, the dialog, YAML preview/edit, the safety model, remembered settings, auto-delete) regardless of the underlying spec; the hand-crafted pod is just the right default for Gardener seed and etcd nodes.

## Develop

Toolchain caches live in `.cache/` inside the repo (no global writes).

```sh
make deps        # Go modules, npm packages, Playwright Chromium
make run         # build and start the app (as bin/kubewing.app, for the Dock icon)
make test        # lint + Go (race) + frontend unit tests
make e2e         # Playwright (Chromium) against the headless backend replaying testdata/tapes
make headless    # bridge over WebSocket on :7777 replaying tapes + testdata/catalog.yaml (TAPES= for real kubeconfig)
```

Browser dev against the headless backend: `make headless` and
`cd frontend && VITE_KW_TRANSPORT=ws npx vite`.

## Layout

| Path | What |
|---|---|
| `internal/pipeline` | pipeline model (source → stages → render), YAML (de)serialization |
| `internal/expr` | CEL (cel-go, plus `sum()`) and dot paths |
| `internal/normalize` | noise rules + content hash |
| `internal/source` | Table list/watch, ref-counted shared registry, discovery + metadata-only lists/watches/gets (also by owner kind, for the jump menu); actions (describe, delete, exec, debug containers, node shells, port-forward) |
| `internal/catalog` | per-context completion snapshot (resource types, namespaces), background refresh |
| `internal/config` | `~/.kubewing/` loader (config, keybindings, themes); invalid parts reported, defaults used; `history.yaml` (recent debug container and node-shell images, window size) |
| `internal/safety` | per-context rules, two-phase mutations (prepare → single-use token → execute) |
| `internal/view` | pipeline over events → keyed diff → viewport frames |
| `internal/bridge` | frontend API, ≤10 Hz frame pump, WebSocket transport |
| `internal/relations` | the jump menu's relations (namespace, owners, owned) of an object, each as a pipeline target; pure |
| `internal/tape` | scenario tapes (goldens, headless E2E); fake catalog for completion (`testdata/catalog.yaml`); fake actions (echo shell, port-forward); `filter: true` tapes (`rel-*`) honor namespace and selectors and serve metadata, as a fake API for the jump menu |
| `frontend/src` | React 19 + Compiler, Glide grid, zustand, transport (Wails / WS) |
| `frontend/src/complete` | completion: pure ranker + candidate providers (reused by the P1 palette), combobox, catalog hook |
| `frontend/src/store/dock.ts` | pure converters between the store's split tree (source of truth) and dockview's layout |
| `frontend/src/editor` | Monaco, trimmed to a lazily loaded read-only YAML/text and diff viewer |
| `frontend/src/term` | xterm.js terminal and exec session output store |

## Tests

- **Goldens** (`internal/view/testdata/*.golden`): tapes in `testdata/tapes/` replayed through the view; frames compared to the golden files. They are the spec: change them only with `make golden-update` and review the diff on its own.
- **Properties** (`rapid`): sort doesn't affect markers, no-op relist produces no frame, rows never leave the viewport, no unchanged resends.
- **Bridge budget**: 10k objects under an event storm → ≤10 Hz, ≤ viewport rows per frame.
- **Catalog**: never connects to a context without an open pane; partial discovery stays usable; failed refreshes keep the last good state; CRD/namespace watches and resolve misses trigger refetches.
- **Frontend units**: keymap (incl. collisions, suppressed webview defaults), layout/command/MRU invariants under 3000 random ops, directional tile focus, cell layout, row cache, completion ranking/highlight goldens.
- **E2E**: Playwright drives Chromium; asserts via `window.__kw.inspect()` and ARIA snapshots.
